# 招才官：安装与第一次使用

招才官是 **HR 的本地招聘工作台**。先用两份虚构 TXT 简历体验本地流程，需要时再准备截图、PDF 或 AI。

当前为 [1.0.1 候选版（预发布）](https://github.com/denggui-ai/zhaocai-guan/releases/tag/v1.0.1-rc.1)，首发仅 Mac Apple 芯片。本轮已用虚构资料验证本地核心流程与同机原路径恢复；逐项结果和未测范围见发行说明。干净 Mac 安装、真实 AI 服务等仍未验收。

[下载 Mac Apple 芯片版（DMG）](https://github.com/denggui-ai/zhaocai-guan/releases/download/v1.0.1-rc.1/ZhaocaiGuan-macOS-arm64-1.0.1-20260930-r5-internal.dmg) · [下载体验材料 ZIP](https://github.com/denggui-ai/zhaocai-guan/releases/download/v1.0.1-rc.1/ZhaocaiGuan-demo-materials-1.0.1.zip) · [看实际界面](DEMO.md) · [常见问题](#help)

<a id="install"></a>
## 安装到 Mac

首发目标是 Mac Apple 芯片（Apple Silicon / arm64）。在苹果菜单的“关于本机”确认芯片；Intel Mac 目前只有未验收的源码，Windows 首发无安装包，Linux 未支持。

1. **下载应用。** 推荐 [Mac Apple 芯片 DMG](https://github.com/denggui-ai/zhaocai-guan/releases/download/v1.0.1-rc.1/ZhaocaiGuan-macOS-arm64-1.0.1-20260930-r5-internal.dmg)，并取得[安装包 SHA-256 校验文件](https://github.com/denggui-ai/zhaocai-guan/releases/download/v1.0.1-rc.1/ZhaocaiGuan-macOS-arm64-1.0.1-20260930-r5-internal-SHA256SUMS.txt)；应用 ZIP 是备选，两种格式选一种即可。体验材料 ZIP 和源码 ZIP 都不是桌面应用。
2. **核验并安装。** 按下方方法核对校验值。DMG 双击打开，ZIP 则先完整解压，再把 `招才官.app` 拖到“应用程序”；不要在压缩预览中运行。已有版本先正常退出并备份。
3. **首次打开。** 当前候选未获 Apple 公证。确认来源可信、文件完整后尝试打开；若系统拦截，到“系统设置 → 隐私与安全性”查看“仍要打开”，按系统提示确认。步骤以 [Apple 官方说明](https://support.apple.com/en-au/102445)为准。不要关闭全局安全保护；提示恶意软件或文件损坏时停止并核查。

DMG 和 ZIP 下载其中一种即可，再取得同版本的外部 SHA-256 校验文件。用终端的 `shasum -a 256` 计算你实际下载文件的 SHA-256（输入命令和一个空格，再将文件拖入终端后回车），只与校验文件中相同文件名的条目逐字符核对，不需要为校验再下载另一种格式。SHA-256 用于核对文件是否与发布记录一致，不证明发布者身份，也不等于 Apple 公证。下载来源或版本不明时，先联系维护者核对。

<a id="first-use"></a>
## 用虚构材料完成第一轮操作

先[下载体验 ZIP](https://github.com/denggui-ai/zhaocai-guan/releases/download/v1.0.1-rc.1/ZhaocaiGuan-demo-materials-1.0.1.zip)并解压，打开其中的 `README.md`。如需核验文件，使用[样例 SHA-256 校验文件](https://github.com/denggui-ai/zhaocai-guan/releases/download/v1.0.1-rc.1/ZhaocaiGuan-demo-materials-1.0.1-SHA256SUMS.txt)；[材料清单](examples/README.md)也可在线查看。所有资料都标注为虚构，外部 AI 保持关闭；不连接招聘平台、不录音。

### 1. 建立一个岗位

进入“职位管理 → 新建岗位”，填入：

- 岗位名称：电商运营专员（虚构体验岗位）
- 负责人：体验HR
- 招聘人数：1

保存后，确认岗位出现在台账，并成为顶部当前岗位。使用专门的虚构岗位，避免把样例和真实候选人混在一起。

### 2. 启用 JD，再确认画像

进入这个岗位的“管理 JD/画像”：

1. 复制[虚构 JD](examples/01-虚构岗位JD.txt)到编辑区，点击“保存 JD 草稿”。
2. 在 JD 的“版本记录”核对内容，点击“启用此版本”。只保存草稿还没有启用。
3. 按[画像参考](examples/02-岗位画像填写参考.md)填写岗位职责、必须条件和加分项。测评策略选“不要求”，客观门槛保持关闭。
4. 点击“保存岗位画像草稿”，在画像的“版本记录”核对关联 JD 后点击“确认此版本”。

重新进入页面，检查 JD 为启用状态、画像为已确认状态。这里不需要 AI 优化或生成深度画像。

### 3. 上传简历并确认建档

确认顶部仍是虚构岗位，进入“候选人 → 上传简历建档”，选择样例包中的第一份 TXT 简历。

在“确认简历建档”窗口核对岗位、文件、姓名和“识别正文预览”。预期显示“正文已提取”。你可以先取消一次，确认列表没有新增，再重新选择并点击“确认建档”。

| 简历 | 应核对的基础信息 |
|---|---|
| 示例林禾 | 本科、虚构示例大学、4年、9-11K |
| 示例周宁 | 本科、虚构练习大学、2年、8-10K |

年龄和联系方式有意留空，不要编造补齐。第一份确认后应新增 1 人；再导入并确认第二份，当前虚构岗位应有 2 人。上传 JD 文件不能替代上传简历。

打开详情，对照原始简历检查工作、教育和项目内容；第一份有两段工作经历，第二份有一段。确认建档只创建本地记录，不会自动评级、联系候选人、排面试或调用 AI。

### 4. 查看记录与下一步

在“资料评估 / 人工处置”中查看证据和可选动作。决定由 HR 作出，样例没有标准档位或录用答案。需要继续体验时，可在“面试安排”手工记录未来时间，注明“虚构演练，无需联系”，不填写真实会议链接。

正常退出并重开应用，选回虚构岗位，检查 JD、画像、2 位候选人及材料仍在。**首次体验完成标准：正确岗位下有 2 位候选人，原始材料可打开，正常退出重开后仍保留。** 这是你在自己环境中应核对的结果；本轮合成资料验收范围见发行说明，遇到差异请记录步骤。

<a id="screenshots"></a>
## 再试截图导入

入口是“候选人 → 候选人操作 → 导入 Boss App 截图”。只使用有权处理的截图；招才官与 BOSS 直聘无官方关联，也不会登录或自动获取平台资料。

Mac 使用系统 Vision，本版仍需可用的 Swift 工具链。截图先成为 OCR 待校对草稿，人工对照原图、修正并确认后才正式入库。草稿可能属于专用截图岗位，系统不会自动切换顶部当前岗位；请查看任务或草稿标注的岗位，再手动切换。不要因为当前列表没有变化就重复导入。

本样例包没有截图或 PDF。非 macOS 截图需逐图批准发送给外部多模态 AI；安装 Tesseract 不能开启离线截图路径。

<a id="optional-tools"></a>
## 按需要准备本地工具

TXT 简历与基本管理无需安装下表工具。当前应用不打包这些可选依赖。

| 能力 | 工具与检查 |
|---|---|
| Mac 截图 OCR | `/usr/bin/swift` 调用系统 Vision；需要 Xcode 命令行工具或完整 Xcode |
| PDF 文字、信息与预览 | Poppler 的 `pdftotext`、`pdfinfo`、`pdftoppm` |
| 扫描 PDF OCR | Mac 可使用 Vision；其他受测文档路径可使用 Tesseract 和 `chi_sim` / `eng` 语言包 |
| Mac 录音与转写 | SoX 的 `rec` / `sox`、`whisper-cli` 和本地 GGML 模型 |
| 音视频格式转换 | Mac 的 `afconvert`；可选 `ffmpeg` 后备 |

**截图识别**：没有 Xcode 命令行工具时，可按 [Apple 说明](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools)运行 `xcode-select --install`，安装后用 `/usr/bin/swift --version` 检查。仅有文件路径不代表工具链已就绪。

**PDF**：已安装 Homebrew 的 Mac 可运行 `brew install poppler`，对应 [Poppler 配方](https://formulae.brew.sh/formula/poppler)。

**本地转写**：已安装 Homebrew 时，可运行 `brew install sox whisper.cpp`，对应 [SoX](https://formulae.brew.sh/formula/sox)和 [whisper.cpp](https://formulae.brew.sh/formula/whisper.cpp)配方。模型另行取得：使用 [whisper.cpp 项目](https://github.com/ggml-org/whisper.cpp)说明中的下载方式，将 `ggml-base.bin` 放在 `~/.cache/whisper.cpp/ggml-base.bin`，或用 `WHISPER_CPP_MODEL` 指定本机文件。

设置页的“检查软件依赖”检查面试软件工具，不证明截图/PDF 全部可用，也不访问麦克风。录音前取得参与者同意，再由使用者主动测试麦克风。Windows 本地录音与转写已禁用，安装工具不会解除限制。更多诊断见[开发指南](../DEVELOPMENT.md#local-tools)。

<a id="optional-ai"></a>
## 需要时再配置 AI

先查看[五项 AI 能力、使用入口与验证状态](AI-CAPABILITIES.md)，按实际任务准备岗位、简历、访谈或已确认报告。设置页连接可用不代表每项业务材料都已准备好。

外部 AI 默认关闭，手工流程可以继续使用。已用虚构材料完成 DeepSeek `deepseek-flash` 的一次 JD 起草实测，其他任务与服务尚未验收；不提供内置免费额度。见[实际输入、输出和已知误报](AI-DEMO.md)。

1. 从你有权使用的服务取得 **HTTPS OpenAI-compatible API 根地址、访问密钥和模型 ID**。服务需要支持 Chat Completions；不要填写网页聊天页面地址。
2. 进入设置中的“外部 AI 辅助”，展开“高级设置：服务地址、访问密钥与模型”。填写服务商标识、根地址和密钥，保存。
3. 刷新并验证可用模型；服务未提供可用列表时，可按界面切换到手动输入模型 ID，再验证。图片任务还需要模型支持图像输入。
4. 验证成功后主动保存并启用。更换服务或密钥会清除旧验证，需要重新配置。
5. 每次实际分析前核对材料预览、服务和发送范围，明确同意后再发送。保存配置不等于材料外发许可。

不同兼容服务的实现可能有差异，能列出模型不等于每项任务都已实测。服务方可能按自己的规则计费、保存或处理内容。密钥不应放进源码、截图、Issue 或日志；系统安全存储不可用时，以界面提示的“仅本次会话”等状态为准。

## 遇到问题

| 现象 | 先检查 |
|---|---|
| 下载后被 macOS 拦截 | 当前未获 Apple 公证；先核对来源和校验值，再按[首次打开步骤](#install)操作；不要关闭全局保护，提示恶意软件或文件损坏时停止并核查 |
| Windows 能安装吗 | 当前没有 Windows 安装包，只有实验源码；不要下载 Mac DMG 或将源码包当成安装包 |
| 一开始就需要 AI Key 吗 | 不需要。先用本页 TXT 样例、岗位管理和手工跟进；AI 默认关闭，按需另行配置 |
| 截图或 PDF 为什么提示缺工具 | 当前包未内置这些可选工具；截图识别需要可用的 Xcode 工具链，PDF 需要 Poppler。可先用 TXT 体验，随后按[工具说明](#optional-tools)安装 |
| 上传后没有候选人 | 是否还停留在“确认简历建档”或截图待校对草稿；顶部岗位是否正确；是否已点击确认 |
| 保存 JD/画像后仍提示未完成 | JD 是否在版本记录中启用；画像是否关联当前 JD 并确认 |
| 截图识别失败 | Swift 工具链是否可运行；截图清晰度及任务错误记录；Mac 不需要为这条本地路径开启 AI |
| PDF 没有正文 | Poppler/OCR 是否可用；现有提示可能未区分文字 PDF 缺工具与扫描件识别失败；可先用 TXT 样例确认基本流程 |
| AI 无法调用 | 服务根地址、密钥与模型是否保存并验证；是否已启用；更换连接后是否重新配置 |
| 重启后 AI 配置不能读取 | 按[凭据恢复步骤](../DEVELOPMENT.md#ai-credential-recovery)备份并恢复，不删除业务库或系统钥匙串 |

使用[中文缺陷报告](https://github.com/denggui-ai/zhaocai-guan/issues/new?template=bug_report.yml)提供应用版本、系统与芯片、安装方式、完成到哪一步、最短复现步骤和错误原文；提交需登录 GitHub。只用样例复现，别公开真实简历、姓名、电话、令牌或密钥。漏洞按[安全策略](../SECURITY.md)私下报告。

<a id="business-restore"></a>
## 业务资料备份、恢复与升级

### 先留下完整备份

在设置页记录本次运行的数据目录、数据库、面试和截图材料的**实际绝对路径**，以及应用版本和原启动路径设置。完全退出应用，确认相关服务和录音进程也已结束，再备份**整个数据目录**；数据库、面试或其他材料若在目录之外，也须一起备份。用同一批次保存这些目录，不只复制 SQLite 主文件；材料、任务以及存在的 sidecar 文件都要保留。

备份包含招聘资料，应放在受限位置。不要在应用仍写入时复制数据库，也不要为试用新版本覆盖唯一备份。

### 恢复整套业务资料

下面适用于**同一台电脑、记录中的原路径**恢复：

1. **完全退出。** 关闭招才官并确认相关进程结束。取得同一备份批次的所有目录、版本记录和原启动设置；信息不完整时先核实，不凭猜测恢复。
2. **保留当前副本。** 将当前受损数据、外置数据库及材料目录整套移到另一个受限位置保留。不要删除唯一副本，也不要将备份直接叠加到仍有旧文件的目录。
3. **恢复原位置。** 把备份中的整个数据目录，以及配套外置数据库、面试等材料目录恢复到记录的原绝对路径。必须使用同一批次的数据库和材料，不能混用旧库与新材料，也不要任意改目录名。部分面试记录引用绝对路径，移动材料不会自动重映射。
4. **保留原启动设置。** 原先指定的用户数据目录、数据库或面试目录覆盖设置应保持一致，防止启动到一个新的空目录。不要为了恢复而临时指定新的存储位置。
5. **用匹配版本启动并抽查。** 使用与备份匹配的应用版本启动，先核对设置页实际路径；再抽查岗位、候选人、原始简历、面试、截图、测评材料和任务状态。遇到缺材料、路径变化或记录不一致时，停止继续写入，保留备份和受损副本用于排查。
6. **单独处理 AI 凭据。** 业务材料恢复不代表系统密钥已恢复。旧 v1 凭据需重新输入和验证；配置读取失败时，按[AI 凭据恢复步骤](../DEVELOPMENT.md#ai-credential-recovery)操作，不删除业务数据库或系统钥匙串。

已完成的是合成资料在同机原路径下的包内模块与隔离文件恢复演练。同机原路径下的实际包恢复复验范围见发行说明；跨机器/跨路径自动重映射以及旧版二进制回滚尚未验证；不要把本步骤当作这些能力已受支持的承诺。升级后也不能只把新数据库交给旧版程序并假定可用。

更名保留历史兼容标识，不要求你手动改目录名。首次恢复建议使用独立的合成资料演练；不要对唯一业务副本做降级或迁移试验。
