## 仓库设置与反馈

发布时检查中文缺陷/建议表单可用、所用标签存在，并启用和验证私密漏洞报告入口，再更新 SECURITY 的条件说明。可按维护能力选择 Issues 或 Discussions 承接安装求助，先把一个渠道维护清楚。当前不要添加假设已存在的表单 URL、邮箱或群二维码。

CI 应展示实际通过的检查与对应平台，不能把 Windows 无头检查等同于 Windows 安装包可用。没有运行记录的徽章不展示为“通过”。

## 发布后的采用情况

优先收集用户自愿提供的安装系统、失败步骤和第一份样例导入体验，用于修复上手阻力。公开下载数反映文件取得次数，星标反映关注，均不直接代表实际 HR 使用量。不默认加入静默遥测，也不收集候选人内容。

推广内容可复用真实演示与入门指南，但外部账号发布、社群消息或活动投放须有对应授权。公开仓库、首次推送及 Release 也需负责人针对最终产物明确确认。
